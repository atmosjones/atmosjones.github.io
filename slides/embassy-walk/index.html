GIS Halloween Spooktacular

Geocoding and the traveling salesman problem

A D.C. tradition: embassy trick-or-treating

  • About 175 embassies in D.C., most along Massachusetts Avenue (“Embassy Row”)
  • Question: what is the shortest walk that visits every one and returns to the start?

Two GIS problems:

  1. Geocoding: we have addresses, not coordinates
  2. Routing: the order of the stops

Step 1: Geocoding

Addresses to coordinates

Geocoding matches a text address to a location, usually by interpolating along a street segment’s address range.

Geocoder Coverage Good for
U.S. Census Geocoder U.S. Free, no account, 10,000 addresses per upload
Nominatim (OpenStreetMap) World Free; one request per second; best with structured fields
DC Master Address Repository D.C. Authoritative D.C. addresses
Google, Esri World Accurate, but paid and licence-restricted

Check your geocodes

  • 113 of 172 landed over 100 m away (median 1.9 km)
  • Albania and Armenia both landed on Madame Tussauds, which has “Washington DC” in its name
  • The Census geocoder slips too: the House of Sweden, 2900 K St NW, came back as K St SE, 8 km away

Geocoding in practice

  1. Save the addresses as a CSV with no header: id, street, city, state, zip
  2. Upload to the Census batch geocoder: geocoding.geo.census.gov ▸ Address Batch
  3. In QGIS: Layer ▸ Add Layer ▸ Add Delimited Text Layer, with the longitude and latitude as X and Y, CRS EPSG:4326
  4. Inspect every match that is not Exact:
    • 170 Exact, 3 Non_Exact (the House of Sweden), 1 Tie
    • The tie was Dominica, whose embassy is at 1001 19th St N in Arlington, VA, outside D.C.
  5. Fix the failures by hand or with a second geocoder, e.g. a structured Nominatim query with street, city and state as separate fields

Rule of thumb: geocoding is never finished until you have looked at the points on a map.

Step 2: The best route

Walking distance, not straight lines

  • Build an origin–destination matrix: the walking distance between every pair of embassies along the street network
  • QGIS: QNEAT3 plugin ▸ OD Matrix from Layers as Table (m:n)
    • Network: D.C. Roadway_Block · Points: embassies (from and to) · ID field: embassy
    • Reproject everything to a metre-based CRS first, e.g. EPSG:26985 (Maryland/D.C. State Plane)
  • 173 × 173 = 29,929 distances
  • Walking is 1.5 times the straight-line distance on our final route

The traveling salesman problem

Visit every stop once and return home, by the shortest route.

\[ number \: of \: possible \: routes = \frac{(n − 1)!}{2} \]

Stops Possible tours
5 12
10 181,440
20 6 × 1016
173 10311
  • Trying every tour is hopeless: 10311 is far more than the ~1080 atoms in the universe
  • Exact solvers exist (Concorde has solved 85,900 stops), but in practice we use heuristics: fast methods that find a good tour, not a guaranteed best one

Heuristic 1: nearest neighbor

Always walk to the closest embassy you have not visited yet.

route = [START]
while len(not_visited) > 0:
    here = route[-1]                    # where we are now
    closest = None
    for embassy in not_visited:         # find the closest unvisited embassy
        if closest is None or distance[(here, embassy)] < distance[(here, closest)]:
            closest = embassy
    route.append(closest)               # walk there
    not_visited.remove(closest)         # and cross it off
  • Simple and fast, but greedy: early choices strand far-away embassies until the end, which forces long legs back across the city
  • From Canada: 76.9 km. The result depends on the start: 76.5 to 88.3 km across all 173 starting embassies

Heuristic 2: 2-opt

  • Take two legs of the tour, a–b and c–d. If a–c plus b–d is shorter, reverse the stretch from b to c
  • Repeat until no swap helps. The tour no longer crosses itself
  • A local optimum: good, but not guaranteed to be the best possible tour

2-opt in the QGIS Python console

improved = True
while improved:
    improved = False
    for i in range(1, len(route) - 2):
        for j in range(i + 1, len(route) - 1):
            A, B = route[i - 1], route[i]
            C, D = route[j], route[j + 1]
            if distance[(A, C)] + distance[(B, D)] < distance[(A, B)] + distance[(C, D)]:
                middle = route[i:j + 1]          # the piece B ... C
                middle.reverse()                 # now C ... B
                route = route[:i] + middle + route[j + 1:]
                improved = True

Scripts: nearest_neighbor_simple.py and two_opt_simple.py. Click the OD table in the Layers panel, then Plugins ▸ Python Console ▸ Show Editor ▸ open ▸ Run.

Result

  • 2-opt cuts the walk by 10%, from 76.9 to 68.9 km
  • 14 hours of walking at 5 km/h
  • 20 hours with 2 minutes per doorstep
